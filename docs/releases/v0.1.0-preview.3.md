# v0.1.0-preview.3 Release Notes

`v0.1.0-preview.3` is the third local MCP preview release candidate for semidx.
It is the [v0.1.0-preview.2](v0.1.0-preview.2.md) surface plus the progressive
MCP discovery and response-budget behavior of
[Plan 009](../plans/009_mcp_progressive_discovery_and_budgets.md).

It is intended for the maintainer and local coding agents. It is not a stable
semantic contract, not a packaged multi-platform binary release, and not a
promise of broad language coverage.

## What Changed Since preview.2

MCP ergonomics and response bounds:

- `semidx_outline` is now the first orientation tool after `semidx_health`. It
  lists immediate directories and files with counts, without listing every
  definition.
- `semidx_references` defaults to `detail: "compact"` and accepts
  `detail: "full"` for the richer shape.
- List tools accept `max_response_bytes`, defaulting to 32000 structured bytes,
  and omit whole items instead of byte-chopping JSON.
- Cut results report `budget_exhausted`, `omitted_by_budget`, and
  `narrowing_hints` that point callers toward narrower or continued requests.
- `semidx_outline`, `semidx_repo_map`, `semidx_find_definitions`, and
  `semidx_references` return authenticated, snapshot-bound continuation
  cursors when more items remain.
- `semidx_context` accepts `direction` and `depth` for bounded graph traversal
  up to three steps.

MCP output shape and tool arguments changed; `semantic_contract_version` is
still `null`. Text fallback duplication is unchanged pending real-client
measurement in
[Follow-up 010](../followups/010_mcp_text_fallback_client_measurement.md).

## What This Preview Provides

- A source-built `semidx-mcp` binary.
- One binary usable against many local repository roots with `--root`.
- Local stdio MCP tools for graph-backed health, outline, repository maps,
  definition lookup, references/calls, focused graph context, traversal, and
  refresh.
- Product version reporting as `0.1.0-preview.3`.
- `semantic_contract_version: null` in MCP structured results.
- Java, Clojure, Zig, source-ingestion, and MCP preview coverage documented in
  the [preview capability matrix](../spec/capability_matrix.md).
- A local habit-loop gate over a temporary copy of this repository and a
  degradation fixture.

## Install And Run

This preview is source-built.

From a checkout with Zig 0.16.0, local tree-sitter runtime prerequisites, and
pinned grammar sources:

```sh
./scripts/setup-tree-sitter-grammars.sh
./scripts/check-zig-version.sh
zig build
zig-out/bin/semidx-mcp --version
scripts/semidx-mcp.sh --root /path/to/repository
```

For client setup and tool details, see
[Local MCP preview](../mcp/local_preview.md).

## Source Data Boundary

`semidx-mcp` is a local process. It does not contact a network service while
indexing or answering tool calls.

Source text is off by default. Without `--allow-evidence-text`, MCP results do
not include file contents, function bodies, or snippets. Results do include
source-derived graph values such as paths, entity names, unresolved designators,
ranges, diagnostic messages, resolution metadata, freshness, producers, and ids.

If a hosted MCP client launches the local server, that client may forward
returned graph values to its model or service. semidx cannot see or enforce
what the client does after receiving results.

`--allow-evidence-text` additionally returns each claim's recorded evidence text,
bounded to 400 bytes per claim. Current producers record names or designators as
evidence text, not source bodies.

## Known Limits

- No stable semantic contract or schema set is published.
- No persistence, file watching, daemon lifecycle, HTTP transport, package
  distribution, binary artifacts, resources, prompts, subscriptions, embeddings,
  or ranking.
- The MCP response budget applies to structured output; every successful tool
  result still repeats the same object as JSON text for client compatibility,
  so wire payloads are about twice the structured size.
- `semidx_health` and `semidx_refresh` are not budgeted, though their size does
  not grow with the number of definitions.
- An explicit `max_response_bytes` up to 2000000 can still return a large
  response.
- Zig cross-unit calls are recorded only through local relative `@import`
  aliases. Calls through receivers and values (`self.x()`), package imports
  (`std.…`), nested namespaces (`alias.Container.foo()`), and container members
  stay unresolved
  ([follow-up 006](../followups/006_zig_cross_unit_and_member_calls.md)).
- A Zig unit importing a relative file that does not exist yet is not
  reanalyzed when the file appears; refresh after editing the importer. Its
  calls through that alias stay unresolved meanwhile, never false facts.
- Clojure symbols stay unresolved wherever a local binding cannot be ruled out
  ([follow-up 008](../followups/008_clojure_lexical_scope_coverage.md)).
- Java same-package type resolution treats the indexed root as one classpath
  ([follow-up 003](../followups/003_java_classpath_boundaries.md)).
